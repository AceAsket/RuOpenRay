# Релизы RuOpenRay

Каждый GitHub Release должен объяснять, что изменилось. Не публикуем релиз только с бинарниками и пустым описанием.

## Что писать в релизе

Минимальный формат:

```md
## Что нового

- ...

## Исправлено

- ...

## Для кого важно

- ...

## Проверки

- `go test ./...`
- `npm run test:frontend`
```

Если релиз технический, все равно пишем человечески: какая проблема исправлена, какие роутеры/режимы затронуты, нужно ли перезапускать Xray и есть ли риск для firewall/DNS.

## Перед публикацией

1. Проверить `README.md`, `docs/api.md` и скриншоты, если менялся интерфейс.
2. Убедиться, что новая версия не оставляет пользователя без понятного rollback.
3. Прогнать тесты:

```sh
go test ./...
npm run test:frontend
```

4. Для изменений firewall/DNS дополнительно проверить стенд OpenWrt.
5. В тексте релиза явно указать, если:
   - менялись nftables/firewall;
   - менялся LAN DNS/dnsmasq/AdGuard Home;
   - менялась логика подписок или профилей;
   - менялась совместимость с Podkop/B4;
   - Xray перезапускается или, наоборот, не должен перезапускаться.
