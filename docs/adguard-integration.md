# AdGuard Home и защищённый DNS

Интеграция в `5.0-test` предназначена для уже установленного AdGuard Home. Панель не устанавливает AdGuard и не перенастраивает DNS LAN при подключении API. В DNS → «Рекламорезка» доступны состояние сервиса и фильтрации, статистика за период AdGuard, переключатель защиты, проверка домена и добавление/удаление исключений. Для управления списками фильтров остаётся штатный интерфейс AdGuard.

## Прямой DoH без зависимости от VPN

Для рабочего роутера выбрана схема `dnsmasq → AdGuard Home → HTTPS DoH`.
Общие upstream — `https://8.8.8.8/dns-query` и `https://9.9.9.9/dns-query`.
IP-адрес в HTTPS URL не требует bootstrap; AdGuard проверяет сертификат сервера.
Общий fallback и HTTP proxy пустые. Основной Xray не участвует в DNS-пути.
При остановке VPN DNS продолжает работать, если интернет и хотя бы один
выбранный DoH-сервер доступны. Блокировка обоих DoH-серверов всё ещё приведёт
к отказу DNS; автоматического перехода на открытый UDP/53 нет.

Панель показывает «DoH напрямую» для конфигураций с общими HTTPS upstream
по публичным IP. Доменное правило, plaintext fallback или внешний файл
upstream не должны ошибочно подтверждать независимый DNS. Для hostname DoH,
других зашифрованных протоколов и внешних списков статус остаётся
неподтверждённым: требуется отдельная проверка реального пути.

Сервис `ruopenray-adguard` запускает только AdGuard Home, когда
`doh-relay.json` отсутствует. Это не требует установленного Xray.
Существующий пилот с файлом relay продолжает запускать оба процесса.
Перенос прямой схемы не требует изменения или перезапуска основного Xray,
установки B4 либо изменения firewall. Проверки остановки VPN и отката
сначала выполняются на тестовой VM, затем на рабочем роутере переключается
только upstream dnsmasq после проверки нового локального DNS.

## Прежний пилот через SOCKS Xray

```text
Устройство → dnsmasq:53 → AdGuard:10536
  → DoH (Google:10535 / Quad9:10537, локальный TLS-транспорт)
  → SOCKS Xray:10808 → VPN → DoH-провайдер
```

TLS не завершается в транспорте: сертификат и имя DoH-провайдера проверяет AdGuard. Транспорт пересылает TCP через основной VPN и не ограничивает типы DNS-записей. `http_proxy` AdGuard используется для HTTP-загрузок и сам по себе не направляет DNS upstream через SOCKS. Xray DNS outbound в проверенной версии 26.3.27 не заменяет этот транспорт для TXT/MX/HTTPS.

Направление TCP-соединений DoH выбирают правила основного Xray. Для схемы через VPN соединения транспорта должны попадать в proxy. Панель обнаруживает путь до SOCKS Xray; для произвольного профиля это само по себе не доказывает выбор VPN правилами маршрутизации.

DoH stamps используют bootstrap IP `127.0.0.1` и TLS provider name с портом, например `dns.google:10535`. Порт в provider name обязателен для dnsproxy, используемого AdGuard Home 0.107.79. Порты 10535/10537 принимают TLS, поэтому значение `127.0.0.1:10535` как обычный DNS upstream неверно.

Основной Xray сохраняет локальный SOCKS-вход `127.0.0.1:10808` без авторизации. При включённой интеграции изменение этого входа в активной конфигурации отклоняется с объяснением: сначала нужно согласовать транспорт. Профили без такого входа можно сохранить, но нельзя активировать с действующим транспортом. Фильтрация DNS не убирает рекламу, размещённую на одном домене с основным контентом.

## Bootstrap и владение настройками

Имена VPN-серверов не должны зависеть от самого VPN. RuOpenRay берёт адреса серверов из активной конфигурации, сохранённых профилей и кандидатов подписок: `vnext`, `servers` и WireGuard `peers`. Домены маршрутизации и общих DoH upstream не добавляются в исключения. IP-адресам bootstrap не нужен.

Перед записью конфигурации/профиля или запуском Xray синхронизация получает текущие `dns_info` и `filtering/status` через локальный API AdGuard. Она добавляет domain-specific upstream на DoH с IP-адресом (по умолчанию Google и Cloudflare) и разрешающие правила для серверов. Имена сохранённых профилей и прежней активной конфигурации сохраняют возможность переключения и отката. После удаления/замены профиля кнопка «Синхронизировать сейчас» или следующий запуск Xray очищает ставшие ненужными записи.

Изменяются только `upstream_dns` и необходимые пользовательские правила. Остальные параметры AdGuard, включая fallback, фильтры, DHCP и TLS, сохраняются. Интеграция не добавляет общий DNS fallback. Для прежней схемы через SOCKS без обхода VPN список общего `fallback_dns` должен быть пустым, а общие upstream — только через транспорт.

В `adguard.json` сохраняются точные записи, которыми владеет интеграция. Совпадающее уже существующее пользовательское исключение не становится управляемым автоматически. Первый переход с ручного пилота может явно использовать `adoptExisting: true` в запросе `configure`; тогда принимается только точное поколение записей для обнаруженных VPN-серверов. Пользовательские изменения из штатного UI AdGuard не следует выполнять одновременно с синхронизацией.

Перед изменением API записывается промежуточное владение обоими поколениями. После прерывания следующий запуск синхронизации может очистить частично добавленное поколение. При ошибке API или локальной записи изменения AdGuard откатываются; кандидат VPN не записывается. Если откат API тоже недоступен, возвращается явная ошибка и промежуточное владение сохраняется для восстановления. Сохранение известного резервного Xray-конфига остаётся возможно без API AdGuard.

Отключение автоматической синхронизации сохраняет последнее поколение bootstrap и разрешающих правил: текущий VPN должен запускаться и после перезагрузки. Для добавления новых серверов синхронизацию нужно включить снова. Переключатель «Выключить фильтрацию» отключает только protection AdGuard, сохраняя DoH и bootstrap. Для полного возврата к прежнему DNS используется резервная копия DHCP и остановка отдельного сервиса AdGuard.

## Файлы и запуск на OpenWrt

Пилот использует `/etc/ruopenray-adguard/AdGuardHome.yaml`, `/etc/ruopenray-adguard/doh-relay.json` и каталог данных `/opt/ruopenray-adguard`. В репозитории сохранён procd-сервис `packaging/openwrt/files/etc/init.d/ruopenray-adguard`. Он требует заранее установленных бинарников и конфигурации; установка пакета панели не включает его автоматически.

Транспорт запускается через отдельное имя `doh-transport`, чтобы статистика основного Xray не учитывала вспомогательный процесс. Жёсткая ссылка экономит место, а при замене ядра обновляется при запуске сервиса. Для разных файловых систем предусмотрено копирование. После обновления Xray нужно перезапустить `ruopenray-adguard`, чтобы транспорт использовал тот же бинарник.

Адрес API допускается только на числовом loopback HTTP(S), без userinfo и редиректов; пароль не отправляется на удалённый адрес. Сохранённый пароль можно оставить прежним, передав пустое поле. API панели защищён её существующей авторизацией. Настройки и резервные копии AdGuard могут содержать секреты: храните их с ограниченным доступом.

## Перед переносом

Проверки выполняются на отдельной VM `192.168.50.117`. Рабочий роутер `192.168.50.1` при подготовке не меняется. Перенос требует отдельной сверки портов, SOCKS-входа, существующего AdGuard и свободного места на целевом роутере.

1. Сохранить бинарник панели, данные, конфигурацию Xray, DHCP и AdGuard. Обеспечить независимый SSH-доступ и путь возврата dnsmasq к прежним DNS.
2. Проверить A/AAAA/TXT/MX/HTTPS по UDP и TCP, рекламу и обычные сайты, добавление и удаление исключений, выключение и включение защиты.
3. Добавить новый сервер в профиль и убедиться, что его имя автоматически попало в bootstrap. Проверить переключение профиля и обновление подписки.
4. Остановить основной Xray на VM: в прямой схеме все проверяемые типы DNS должны работать после очистки кэша. В прежней схеме через SOCKS общий DNS должен завершаться ошибкой без прямого fallback, а имена VPN-серверов — разрешаться.
5. Проверить отказ API AdGuard: конфигурация VPN не должна измениться. Затем восстановить сервис и повторить синхронизацию.
6. Перезагрузить VM, проверить восстановление сервиса, фильтрации, bootstrap и VPN; выполнить откат к прежнему DNS и возврат к пилоту.

Официальные интерфейсы: [API AdGuard Home 0.107.79](https://github.com/AdguardTeam/AdGuardHome/blob/v0.107.79/openapi/openapi.yaml), [настройки AdGuard Home](https://adguard-dns.io/kb/adguard-home/configuration/), [DoH stamps](https://dnscrypt.info/stamps-specifications/).
