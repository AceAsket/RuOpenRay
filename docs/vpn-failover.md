# Резервирование VPN и балансировка

В разделе «Подключения → Балансировка → Группы серверов → Добавить» есть два режима:

- **Основной → резервный VPN.** Один основной сервер проверяется Xray. После обнаружения отказа новые соединения идут в резервный выход. После успешной проверки основной снова получает новые соединения. Уже открытые соединения не переносятся.
- **Балансировка соединений.** Случайный выбор, round robin, минимальная задержка (`leastPing`) или выбор лучших участников (`leastLoad`). Настройка `expected` задаёт число лучших серверов для leastLoad. Это распределение соединений, а не объединение скорости каналов для одной загрузки.

Группа используется только правилами с её `balancerTag`. Сохранение меняет черновик. Для запуска нужно выбрать группу в нужных правилах, проверить конфигурацию и применить её обычным способом. Остальные правила и DNS сами не меняются.

## Проверки и отказ

Обычная проверка Observatory выполняет HTTP-запрос через каждый выбранный VPN. Новые настройки включают параллельные пробы. Интервал по умолчанию 10 с, таймаут пробы в Xray фиксирован — 5 с. Отказ обнаруживается после неудачной пробы; возврат происходит после успешной. Это не мгновенная миграция соединений и не проверка доступности всех сайтов.

Burst Observatory делает серии проб со случайным временем запуска. Можно задать интервал, таймаут и размер серии; URL должен возвращать HTTP 204. Отказ может обнаруживаться за 1–2 серии, восстановление — до одной серии. Большая серия сглаживает единичные сбои, но замедляет реакцию.

URL, тип и интервалы наблюдения **общие для всех групп профиля**. Смена типа объединяет списки наблюдения и оставляет один источник результатов: Xray получает Observatory как одну feature. leastLoad с обычным наблюдением использует задержку; серия дополнительно даёт разброс задержки и долю ошибок. CPU и текущую пропускную способность VPN этот механизм не измеряет.

Случайный выбор и round robin исключают известные недоступные выходы только при наличии наблюдения и `fallbackTag`. Панель добавляет оба при включённой проверке доступности. Если резерв не выбран, создаётся или используется выход `blackhole`, чтобы отказ всех участников не отправлял трафик в выход по умолчанию. До первой пробы random/roundRobin считают участника доступным; leastPing/leastLoad ждут результата и используют fallback.

В режиме основной/резервный резерв — безусловный `fallbackTag`, а не ещё одна группа с рекурсивным выбором. Если недоступен и он, соединение завершится ошибкой. Для нескольких взаимозаменяемых каналов используйте балансировку с проверкой доступности. Автовозврат на основной встроен; задержки возврата и пороги последовательных ошибок для обычного Observatory не предлагаются, поскольку Xray их не поддерживает.

Селекторы Xray сопоставляются по префиксу. Для режима основной/резервный панель отклоняет неоднозначный тег основного сервера. В редакторе балансировки импортированные префиксы поддерживаются. При редактировании сохраняются дополнительные `strategy.settings`, включая веса, baselines, maxRTT и tolerance. Переименование группы обновляет ссылки в правилах в том же черновике.

Round robin использует отсортированные теги выходов: перестановка селекторов не меняет порядок ядра. Редактор объясняет это и не показывает неработающие кнопки перестановки.

Недоступность проверочного сайта может вызвать переключение исправного VPN. Выбирайте URL, который устойчиво доступен через используемые каналы. Ручные проверки панели не управляют выбором Xray.

## Проверка совместимости

`TestXrayBalancerRecovery` запускает отдельный настоящий Xray с управляемыми локальными HTTP-прокси. Проверяет основной/резервный канал, все четыре стратегии, исключение отказавшего участника, отказ всех каналов, восстановление и автоматический возврат. Дополнительный сценарий проверяет leastLoad с Burst Observatory. Перед проверкой маршрута тест дожидается фактического Alive-статуса обоих каналов из локального `/debug/vars` Xray, чтобы случайная серия выбора резерва не считалась обнаружением отказа. Первый выход специально отвечает `LEAK`: его выбор считается ошибкой. Тест не использует публичные сайты и не меняет активную конфигурацию роутера.

CI запускает этот тест с Xray 26.3.27, 26.9.9 и 26.10.21. Frontend-тесты проверяют формирование и атомарное сохранение черновика, валидацию, сохранение дополнительных настроек и покрытие селекторов.

На тестовой OpenWrt VM 192.168.50.117 с Xray 26.10.21 итоговый прогон всех шести сценариев с ожиданием статуса ядра прошёл за 61 с. В браузере проверено создание группы, сохранение после перезагрузки и открытие с прежними основным/резервным сервером. Установленный Xray принял сформированный интерфейсом черновик. Тестовая группа удалена после проверки; исходное состояние черновика, активная конфигурация, PID Xray/AdGuard, firewall и таблицы маршрутизации сохранены. На 192.168.50.1 изменения не переносились.
