# Полная копия настроек и восстановление

## Точка отката быстрого запуска

Мастер сохраняет исходную конфигурацию Xray, LAN DNS и nftables на роутере
в приватном файле `DataDir/setup-snapshot.json` с правами `0600`. Снимок
доступен после обновления страницы, повторного входа и перезапуска панели.
Он содержит секреты конфигурации и не записывается в localStorage браузера.

Мастер записывает состояние восстановления перед изменением Xray и DNS.
Если снимок нельзя сохранить, следующий шаг не выполняется. Незавершённый
запуск сохраняет исходную точку для повторной попытки и ручного отката.
Изменения снимка из другой вкладки проверяются по ревизии.

Кнопка «Забыть снимок» удаляет только точку восстановления; сетевые настройки
не меняются. После успешного отката снимок удаляется. Сохранение снимка
не означает автоматического отката всех шагов мастера при перезагрузке роутера.

## Полная резервная копия

Настройки → «Хранилище» → «Полная резервная копия» позволяет создать ZIP,
проверить его и скачать на компьютер. Тот же API доступен независимо от интерфейса.

Копия включает активный JSON Xray, профили и постоянные данные панели
(подписки, названия и группы правил, настройки интеграций), UCI `ruopenray-ui`,
`xray`, `dhcp`, `network`, `firewall`, init-скрипты панели, Xray и
`ruopenray-adguard`, найденный YAML AdGuard и его локальные `.txt` списки.
Не включаются журналы, временные проверки, вложенные копии, бинарники,
geo-базы, статистика и журнал AdGuard, вся прошивка или native настройки B4.
Это восстановление настроек на подготовленной системе с установленными
службами, а не образ диска для пустого роутера.

ZIP и каталог копий доступны только владельцу на Linux: `0600` и `0700`.
Архив содержит пароли, ключи VPN и интеграций. Храните скачанный ZIP как
секретный файл. Манифест содержит SHA-256 и размер каждого файла; это проверка
целостности, а не цифровая подпись или шифрование. Проверка запрещает выход за
допустимые пути, повторяющиеся назначения и символические ссылки. Ограничения:
2048 файлов и 128 МиБ распакованных данных. Старые ZIP без манифеста можно
разобрать вручную, автоматическое полное восстановление их отклоняет.

## API

Все вызовы требуют входа в панель. `path` должен указывать на ZIP внутри
настроенного каталога BackupDir, обычно `/etc/ruopenray-ui/backups`.

```text
POST /api/backup/full                 {}
POST /api/backup/full/check           {"path":"/…/ruopenray-full-….zip"}
GET  /api/backup/full/download?path=<URL-encoded-path>
POST /api/backup/full/restore         {"path":"/…/ruopenray-full-….zip","offline":true}
```

Создание возвращает `ok` и `path`. Проверка сверяет состав и хеши, затем
проверяет JSON установленным Xray и YAML установленным AdGuard. Она ничего не
восстанавливает. Скачать архив можно по cookie панели или Bearer token;
ответ отдаётся как ZIP attachment с `Cache-Control: no-store`.

## Окно восстановления на OpenWrt

1. Сохраните текущую копию вне роутера и обеспечьте независимый SSH-доступ.
   Не редактируйте одновременно профили, сеть или AdGuard в другой панели.
2. Проверьте выбранный архив через `/backup/full/check` до остановки служб.
3. Остановите `/etc/init.d/xray` и `/etc/init.d/ruopenray-adguard` по SSH.
   Ручка восстановления отклоняет запрос, пока найден процесс Xray или AdGuard.
4. Отправьте `/backup/full/restore` с `offline:true`. До первой записи создаётся
   обязательная копия текущего состояния. При ошибке записи уже изменённые
   файлы откатываются; результат сообщает путь `rollbackBackup` и ошибки отката.
   Более новые постоянные файлы панели и кэш фильтров, отсутствующие в снимке,
   удаляются, чтобы они не подмешивались к восстановленной конфигурации.
5. Запустите AdGuard, проверьте DNS по UDP/TCP, затем запустите Xray и проверьте
   HTTPS через нужный VPN. Для применения UCI и перезагрузки состояния панели
   перезагрузите роутер в это же окно обслуживания. Изменённый LAN IP потребует
   переподключения по адресу из архива.

API не перезапускает службы и сеть автоматически. Откат при ошибке записи
не является защитой от выключения питания посреди операции. Копирование
живых служб не создаёт единый транзакционный снимок всех внешних приложений;
для согласованного снимка исключите параллельные изменения.
