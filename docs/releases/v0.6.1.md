# RuOpenRay v0.6.1

Исправлен ложный сбой горячего применения правил Xray с ошибкой
`AddRule: DeadlineExceeded`. Причина ошибки и результат отката теперь видны
сразу в панели, над техническим отчётом.

## Исправлено

- Полная замена правил и API-откат получают по 20 секунд ожидания RPC вместо
  четырёх. На запуск CLI, чтение конфигурации и завершение команды отводится
  по 30 секунд. Короткий таймаут чтения состояния API остаётся прежним.
- Фоновый `xray api statsquery`, а также команды `version` и `help` больше
  не принимаются за второе работающее ядро при проверке процесса. Проверки
  PID/start time, установленного бинарника, config-файла и API-сокета остаются.
- При ошибке горячего применения панель показывает её причину и подтверждение
  восстановления предыдущей конфигурации. Сообщение больше не сообщает
  об ошибке перезапуска, которого горячий путь не выполнял.
- Развёрнутый технический отчёт ограничен по высоте и прокручивается внутри
  блока, чтобы большой результат проверки отката не занимал всю страницу.

Повторная отправка неудачного кандидата не выполняется: при ошибке RPC
восстанавливаются предыдущие правила и конфигурация. Если API-откат не
подтверждён, предыдущая конфигурация запускается обычным перезапуском Xray.

## Обновление

Обновите панель через диалог её версии или по SSH:

```sh
ruopenray-ui update --backup
```

Версия OpenWrt-пакета — `0.6.1-r1`. Конфигурации, профили, подписки и настройки
локального RoutingService сохраняются. Обновление панели не требует
перезапуска Xray или AdGuard Home. Условия горячего пути остаются прежними:
Xray 26.10.21 или новее, изменение только списка правил, профиль без
балансировщиков или routing script и подтверждённый локальный API.

## Проверки

- Go suite, vet, race detector, установщик и сборки для пяти архитектур.
- 451 frontend-тест, smoke (87 проверок, 67 рендеров) и загрузка приложения.
- Матрица Xray 26.3.27, 26.9.9, 26.10.21 и 26.10.31. Горячий путь проверен
  с задержкой ответа AddRule на пять секунд и параллельным клиентом статистики;
  старый TCP-поток сохраняет выход, новый использует обновлённое правило,
  потерянное подтверждение запускает откат.
- На основном ARM64 OpenWrt-роутере два горячих применения при параллельном
  клиенте статистики сохранили PID/start time Xray и счётчики. Исходная
  конфигурация и профиль восстановлены после изменения только диагностической
  метки правила; условия и направления маршрутов не менялись.

Подробности: [горячее применение правил](../hot-routing.md).
