## Что нового

- Диагностика → TLS: серии настоящих HTTPS-запросов TLS 1.2/1.3 с проверкой
  сертификатов и чтением тела. Сравниваются прямой запрос с роутера, выбранный
  VPN и копия выхода без фрагментации. Рабочий Xray не перезапускается.
  Оборванный ответ HTTP 200, таймаут, TLS и ошибка сертификата показываются
  отдельно; неполная серия не считается успешной.
- DNS → Рекламорезка и Интеграции → AdGuard: список фильтров с количеством
  правил, датой и состоянием, добавление HTTPS URL, переключение, удаление и
  обновление. Пресеты AdGuard DNS, Popup Hosts и HaGeZi Normal заполняют форму.
  Исключения и DoH сохраняются, Xray не перезапускается.
- Настройки → Хранилище: полная ZIP-копия настроек с манифестом SHA-256,
  проверкой и скачиванием. В архив входят профили и группы, настройки LAN DNS,
  native YAML и кэш списков AdGuard. Полное восстановление через API требует
  остановленных Xray/AdGuard, создаёт копию для отката и возвращает уже
  изменённые файлы при ошибке записи. Это не образ прошивки или диска.
- Матрица реального Xray расширена до `26.3.27`, `26.9.9`, `26.10.21`.
  Официальные архивы закреплены по SHA-256. На дату RC2 `26.10.21` является
  prerelease ядра; панель не устанавливает его автоматически.

## Проверка на отдельной OpenWrt VM

Все установки и перезапуски этого этапа выполнялись на `192.168.50.117`.
Рабочий роутер `192.168.50.1` не обновлялся, его маршруты не применялись.

- Go unit-тесты, `go vet`, 132 frontend-теста, smoke и запуск приложения.
- Изолированные VLESS gRPC TLS, Trojan TLS, WS и XHTTP с настоящим ядром;
  неверные учётные данные и недоверенные сертификаты отклоняются.
- Установка `26.10.21` с обязательной копией старого ядра, проверкой активного
  конфига, сохранением LAN DNS и firewall. Первая загрузка с GitHub завершилась
  сетевой ошибкой до замены, действующее ядро осталось прежним; повторная
  контролируемая попытка прошла.
- Виртуальный LAN-клиент: 24 DNS-проверки UDP/TCP, A/AAAA/TXT/MX/HTTPS,
  рекламный домен, IPv4 TPROXY и маршруты direct/VPN/block. Временные правила
  после проверки удалены, исходные конфигурации сохранены.
- Реальные операции с временным фильтром AdGuard, проверка ZIP, полное
  восстановление и DNS без запущенного Xray. Запросы к DoH проверялись на
  случайных некэшированных именах.
- Перезагрузка VM: панель, AdGuard и Xray запустились автоматически, черновик,
  имена групп и подборки сохранились, DNS и HTTPS через VPN работают.

Точная методика и критерии стабильной версии:
[журнал RC2](https://github.com/AceAsket/RuOpenRay/blob/v0.5.1-rc2/docs/reliability-051-rc2.md).

## Ограничения и обновление

Новый клиент Xray не гарантирует устранение плавающих TLS-сбоев конкретного
сервера. На VM с `26.10.21` в одной сравнительной серии TLS 1.3 с фрагментацией
прошли 3/5 запросов к GitHub, без неё — 5/5. Это воспроизведение влияния
конфигурации, а не доказательство единственной причины всех обрывов.
Прямой запрос VM также может перехватываться внешним шлюзом. Автоматического
переключения маршрутов или отключения фрагментации нет.

Повторный прогон после перезагрузки через два VPN без фрагментации дал 35/36
успешных запросов; один завершился таймаутом, через Финляндию — 18/18.
Поэтому RC2 остаётся предварительным релизом для наблюдения в обычной работе.

Обновление только панели не применяет черновик и не перезапускает Xray.
Настройки интеграций применяются отдельными действиями. Для полного
восстановления нужны установленные службы, независимый SSH-доступ и окно
обслуживания; архив содержит секреты. См.
[восстановление](https://github.com/AceAsket/RuOpenRay/blob/v0.5.1-rc2/docs/backup-restore.md).

B4 и штатный IPv6 TPROXY остаются отдельным этапом. Лимит UDP-очереди B4
не обеспечивает постоянный QUIC reject после исчерпания пакетов; обход
провайдерского DPI и IPv6 WAN не подтверждены. DNS-клиент в журнале AdGuard
за dnsmasq по-прежнему отображается как localhost.
