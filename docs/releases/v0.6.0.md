# RuOpenRay v0.6.0

Правила маршрутизации можно применять без перезапуска Xray. В разделе
«Сценарии и правила» также появилась пробная карта действующего nftables.
Версия включает исправления и пагинацию подключений из 0.5.9.

## Что нового

- Горячая замена полного списка `routing.rules`: добавление, удаление,
  перестановка, условия и выбор существующего выхода. Проверка конфигурации,
  Geo Doctor, backup, сохранение профиля и ревизии черновика остаются.
- «Подготовить локальный API» добавляет RoutingService в черновик. Существующий
  loopback API статистики сохраняется; без API используется 127.0.0.1:10086.
  Для первого включения нужен один обычный перезапуск Xray.
- После успешного горячего применения новые соединения используют новые
  правила, уже открытые сохраняют прежний маршрут. Сервис и его счётчики
  продолжают работать. Перед RPC проверяются процесс и владелец API-сокета,
  после RPC — прежний процесс, порядок и направления правил.
- При ошибке RPC восстанавливается весь прежний список и сохранённый config.
  Потеря подтверждения не приводит к повторной отправке кандидата. Если API-откат
  не подтверждён, предыдущая конфигурация восстанавливается обычным перезапуском.
  При неудаче черновик сохраняется.
- Пробная карта firewall: пять этапов Netfilter, сценарии LAN → Интернет,
  LAN → роутер и роутер → Интернет; IPv4/IPv6, все семейства, поиск цепочек,
  приоритеты, счётчики, раскрытие выражений и переходы jump/goto с возвратом.
  Длинные цепочки доступны порциями по 200 правил.

## Исправлено

- Этапы и результат применения показывают горячую замену вместо сообщения
  о перезапуске, которого не было.
- Пустой список балансировщиков, добавляемый интерфейсом, не вызывает лишний
  перезапуск при изменении только правил.
- Отключение статистики сохраняет RoutingService и его локальный транспорт.
  Включение статистики использует существующий упрощённый API без второго listener.
- Упрощена иконка раздела «Сценарии и правила»; новые блоки поддерживают обе темы
  и узкий экран без слипания с соседними карточками.

## Для кого важно и ограничения

Горячий путь требует Xray 26.10.21 или новее на Linux, одного процесса с одним
config-файлом и подтверждённого локального API. Изменения серверов/outbounds,
DNS, domainStrategy, inbounds и прочих параметров используют обычный перезапуск.
Профили с балансировщиками или routing script пока также используют обычный путь:
полная замена через API пересоздаёт балансировщики. При недоступной предварительной
проверке выполняется обычное применение. Параллельное изменение условий правил
сторонними API-клиентами не поддерживается: ListRule не возвращает полные условия.

Карта firewall — снимок только для чтения. Подсветка не является трассировкой
пакета и не предсказывает окончательный verdict. Ускоренный flowtable-трафик
может обходить счётчики; в inet они общие для IPv4/IPv6. Именованные наборы
не загружаются. Отдельного сборщика iptables в этой версии нет.

## Обновление и откат

Пакет OpenWrt — 0.6.0-r1. Обновление только панели сохраняет конфигурации,
черновик, профили, подписки, firewall и DNS. Оно не включает RoutingService
автоматически и не требует перезапуска Xray или AdGuard Home.
Перед установкой сохраняются предыдущий бинарник и настройки; неуспешная
проверка обновления запускает откат.

## Проверки

- 448 frontend-тестов, smoke (87 проверок, 67 рендеров) и загрузка приложения.
- Go suite, race detector, vet, установщик и сборки для пяти архитектур.
- Общая матрица настоящих туннелей Xray 26.3.27, 26.9.9, 26.10.21 и 26.10.31.
  Горячая замена проверена на 26.10.21 и 26.10.31: старый TCP-поток остаётся
  на прежнем выходе, новый использует новый; потерянное подтверждение откатывается.
- На основном ARM64 OpenWrt-роутере два применения и восстановление только
  диагностического ruleTag прошли в режиме hot-routing. PID/start time Xray,
  счётчики, firewall, DNS и исходные config/profile/draft сохранены.
- В браузере: подготовка API, обычное первое применение, последующая горячая
  замена, корректные сообщения и отступы, обе темы, экран 320 px.

Подробности: [горячие правила](../hot-routing.md), [карта firewall](../firewall-map.md).
