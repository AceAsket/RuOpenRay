# Xray 26.10.29: проверка совместимости и обновление роутеров

Проверен официальный [Xray-core v26.10.29](https://github.com/XTLS/Xray-core/releases/tag/v26.10.29),
опубликованный 29 октября 2026 года. После испытаний обновлены `.117` (amd64)
и `.1` (ARM64). Панель остаётся RC5. Серверы VPS в этом этапе не обновлялись.

## Аудит изменений

Между [v26.10.21 и v26.10.29](https://github.com/XTLS/Xray-core/compare/v26.10.21...v26.10.29)
19 коммитов. Для RuOpenRay существенны ограничение размера перехваченных DNS
ответов, уточнение встроенных special/private-IP диапазонов, порядок
инициализации inbound, обработка нормального закрытия WebSocket и ограничения
встроенного загрузчика geodata. Также исправлено определение расширения файла
конфигурации при работе с symlink.

`freedom.settings.fragment` и `noises` ещё принимаются, но Xray предупреждает
о переносе в `streamSettings.finalmask.tcp.fragment` и `finalmask.udp.noise`.
В текущих конфигурациях `.1` обнаружено такое предупреждение о fragmentation;
native validation завершается успешно. Формат фрагментации, маршруты и
параметры VPN в этом обновлении не мигрировались. IPv6/private-IP изменения
не считаются сертификацией native IPv6 WAN/TPROXY.

## Получение и проверки

Оба ZIP сверены с официальными `.dgst` и SHA-256 digest GitHub assets. Из архивов
извлечён только `xray`; geo-базы и другие файлы релиза не подменялись.

| Архитектура | SHA-256 ZIP | SHA-256 бинарника |
| --- | --- | --- |
| amd64 | `8a5f3e6a1057e4bd0f8a7c57c9d91204b4be0b74222a6e210d070603101163c2` | `e783b9d2b46ed1ab3617c59b04dfbce38c999322d018c6e060f18d88bf6158aa` |
| ARM64 | `afe01f19045b05237420328028ee1ee2e1edd2100eb41a8cbbf50e683b0a6e58` | `f02fa77fa2f1a0f8f2b4fd69af5000494bcc3fa4e97899caf023c7f72fd74474` |

При загрузке больших файлов текущий сетевой путь к GitHub давал разрывы и
таймауты. Для получения файла использован временный loopback HTTP proxy через
изолированный Xray `.117` без fragmentation, с прежним проверенным NL-выходом.
ARM64-архив дозагружен проверенными HTTP Range-ответами; итоговый ZIP целиком
совпал с официальным SHA-256. Настройки рабочего VPN на `.1` для этого не менялись.

На `.117` до замены работающего ядра запущены native integration tests из
текущего `dev`: **31 PASS, 0 FAIL, 0 SKIP**. Проверены шесть семейств:
VLESS/Trojan TLS и транспорты подписок, стратегии/восстановление балансировщиков,
доступ к LAN и DNS compatibility, geo-транзакция, назначение при sniffing и
обработка исключений sniffing.

Обнаружены две жёсткие привязки ожиданий к прежним версиям; в них добавлен
`26.10.29`, чтобы новые тесты не пропускались и корректно проверяли запрет LAN
для remote inbound без explicit finalRules. CI-матрица дополнена новой версией
с закреплённым SHA-256 ZIP. [CI для `42519bf`](https://github.com/AceAsket/RuOpenRay/actions/runs/40925445391)
успешен: Go/race/vet/frontend, четыре Xray и сборка пяти архитектур.

Кандидат нативно проверил активный конфиг и два сохранённых профиля на каждом
роутере: **3/3 на `.117`, 3/3 на `.1`**. Черновика на обоих не было; это
состояние сохранено. Логи проверки с потенциальными секретами оставлены только
в приватном локальном каталоге.

## Установка

Сначала обновлён `.117`; после проверки перенесён ARM64-бинарник на `.1`.
Из-за нестабильной повторной загрузки установлен уже проверенный локальный
файл. Операция выполнялась под тем же Linux flock
`/tmp/ruopenray-operation.lock`, который использует RuOpenRay API/cron/CLI.
Под lock повторно проверялись хеши, активный конфиг и native validation.

До замены выделены копия прежнего ядра, архив настроек и rollback-файл на
файловой системе `/usr/bin`. Файл атомарно заменён с `sync`; затем выполнен
перезапуск только Xray. Новый managed PID проверен пятью последовательными
секундными интервалами, SHA-256 `/proc/PID/exe` совпал с установленным ядром.
После функциональных проверок обновление подтверждено; независимый watchdog
имел возможность вернуть прежнее ядро при незавершённой установке.

| Стенд | Старый PID Xray | Новый PID | DNS UDP/TCP | HTTPS через рабочий SOCKS |
| --- | --- | --- | --- | --- |
| `.117` | 4378 | 7491 | 8/8 | 4/4 |
| `.1` | 9387 | 8989 | 8/8 | 4/4 |

DNS включает свежий случайный запрос; HTTPS — Cloudflare, gstatic, Discord
и GitHub favicon. Полный цикл замены/стабилизации/последующих проверок занял
9,3 с на `.117`, 19,0 с на `.1`. Это не измерение длительности разрыва VPN:
перезапуск Xray кратко прерывает существующие соединения.

Active config, draft, профили, UI binary и PID панели/AdGuard, UCI, nftables и
policy routing совпали с исходными снимками. Статус обеих панелей подтверждает
`Xray 26.10.29`, commit `0afec66`, Go 1.27.3. Полная корректность маршрутизации
физического LAN-клиента этим локальным SOCKS-контролем не доказывается.

## Наблюдение и ограничения

Независимый монитор `.1` работал до, во время и после обновления 181,4 с:
DNS **177/177**, HTTPS через VPN **27/27**. Это короткая приёмка доступности,
не замена длительного soak и не утверждение об исправлении прежних плавающих
GitHub/TLS-ошибок.

Из 63 служебных снимков 62 совпали. Один отличался примерно через 100,5 с
после запуска монитора; исходные различающиеся поля не были сохранены.
Эта методика содержит `pidof` и может учитывать короткоживущие CLI-процессы;
точная причина единичного отличия не доказана. Итоговая полная сверка состояний
успешна. Отдельная повторная проверка использует managed PID из procd и
сохраняет различия при несовпадении: **30/30 за 34,7 с**. Managed PID панели
28610, AdGuard 1491 и Xray 8989 сохранились; сеть и nftables совпали.

Старые параметры fragmentation потребуют отдельной, проверяемой миграции на
Finalmask перед будущим удалением совместимости в Xray. Встроенные private-IP
и native IPv6 ограничения требуют отдельной матрицы сценариев.

## Откат и очистка

На обоих роутерах оставлен каталог
`/root/ruopenray-backups/xray-26.10.29-20261029/` (0700): прежний Xray,
архив настроек (0600), SHA-256, журнал установки и независимый watchdog.
Хеши копий повторно проверены. Для ручного возврата подготовлен
`sh /root/ruopenray-backups/xray-26.10.29-20261029/restore-now.sh`.
Он проверяет текущий SHA, backup и совместимость прежнего ядра с текущим
конфигом, затем под flock возвращает только ядро и перезапускает Xray.
Синтаксис проверен; успешное обновление откатом не отменялось.

Временные proxy/test-процессы, loopback forward и каталоги с конфигами
удалены после сохранения результатов. Копии и планы отката остаются на
роутерах; исходники приватных профилей и резервные архивы в Git не включены.
