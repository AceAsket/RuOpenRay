## Выполненные работы

- В `dev` реализован первый пакет конфигураций и обслуживания. API 0.2 требует
  ревизию при сохранении/удалении черновика. Снимок активного конфига и черновика
  защищён тем же Linux flock, что API/cron/CLI; scope блокировки — весь роутер,
  даже если у процессов разные каталоги данных.
- Ошибка restart не удаляет черновик и не отображается как успешное применение;
  следующий шаг комплексного apply прекращается. Фоновые refresh сохраняют
  локальные изменения, конфликт можно разрешить явной загрузкой актуального черновика.
- Смена кандидата подписки сохраняет dialerProxy и согласует saved profile;
  ошибка восстанавливает точный прежний профиль. Restore JSON также синхронизирует профиль.
- CLI читает UCI с приоритетом явных env, не создаёт default ActiveConfig
  и не запускает фоновые обработчики логов. Все cron generators передают пути
  DataDir/ActiveConfig/ProfilesDir/GeoDir/BackupDir/ServiceName и лимиты Go.
- Geo download ограничен 64 МиБ; multipart потоково пишется в файловую систему
  asset-каталога и ограничен до разбора. Полный набор готовится отдельно,
  проверяется protobuf framing и native Xray, затем заменяется с обязательной копией.
  Ошибки скачивания/проверки не изменяют рабочие базы; предусмотрен откат при отказе restart.
- Дополнительно найден и исправлен регистр кодов создаваемых категорий GeoIP/GeoSite:
  теперь на диске UPPERCASE. Проверка настоящим Xray выявила отказ старого lowercase
  кода; [загрузчик ядра 26.10.21](https://github.com/XTLS/Xray-core/blob/v26.10.21/common/geodata/geodat_loader.go)
  сопоставляет байты кода с учётом регистра. Читаемые UI-коды остаются прежними.
  Существующие базы на `.1` автоматически не переписывались.
- Remember-токены используют случайный постоянный ключ вместе с паролем;
  проверка expiry выполняется независимо от session map. Logout сохраняет отзыв
  на диске, обычные сессии ограничены 12 часами, попытки входа ограничены.
  Неавторизованная проверка токена не создаёт ключ на диске.
- SVG проверяется XML-парсером с разрешающим списком и показывается как image,
  добавлены CSP/nosniff/frame headers. Полная browser-приёмка импортов остаётся.
- Самообновление сверяет официальный digest/SHA независимо от зеркала и делает
  обязательную копию; shell installer сверяет SHA, готовит файл на целевой FS
  и сохраняет прежний binary. Watchdog после фактического перезапуска ещё нужен;
  обязательная rollback-копия пока сохраняется независимо от флага keepBackup.
- Диагностика HTTP больше не объявляет обрезанный HTTP 200 успешным; полное
  чтение ограничено 2 МиБ, превышение лимита явно считается неполной проверкой.
- На `.117` пройдены 15 первоначальных Linux regression-сценариев и native
  tunnel/sniffing/balancer suite с Xray 26.10.21. Дополнительный native geo-тест
  подтвердил отказ при исчезновении нужной категории, успешную установку валидной
  базы и native отказ невалидному профилю. Тесты выполнялись в отдельных каталогах.
- Изолированная временная Go-панель `.117` проверена по настоящему HTTP API:
  malformed JSON, stale revision, неудачный restart с сохранением черновика,
  нормализация старого профиля, native validation, logout/restart и действительная
  remember-сессия после restart. PID Xray/AdGuard и хеши действующих файлов `.117`
  до/после совпали. Установленная панель не заменялась. `.1` не изменялась.
- В CI добавлены race detector и native geo-тест для трёх закреплённых Xray.
  [Первый прогон](https://github.com/AceAsket/RuOpenRay/actions/runs/40703834931)
  подтвердил все три версии ядра. Старый unit-тест отказа маркера профиля
  дополнен успешным validator fixture и обязательным BackupDir, чтобы проверять
  сам откат после записи, а не более ранний отказ подготовки. Текущий итог CI
  следует проверять для последнего SHA в Actions.
- `/config/apply` отклоняет отсутствующий, null, строковый и массивный config
  без перезапуска и без изменения файлов; явный restart вынесен в `/service`.

## Второй пакет: firewall, watchdog, runtime health и SDK

Реализация и испытания продолжаются; этот раздел не объявляет стабильный релиз.

- Firewall: `nft --check`, затем один batch delete/create только таблицы
  `inet ruopenray`. Общий reload firewall не вызывается. До изменения ядра
  создаются копии управляемых файлов на их файловых системах, обратный nft batch,
  снимок DHCP и принадлежащих RuOpenRay policy rules/routes. Ошибка следующих
  шагов восстанавливает их; отказ самого отката возвращается отдельно и оставляет
  recovery.json. Таблица 100 с чужими маршрутами/правилами отклоняется без очистки.
  Это компенсация ошибок выполняющейся операции; автоматическое восстановление
  после потери питания посреди транзакции пока не реализовано.
- Hotplug вызывает `--firewall-reload`, использующий общий межпроцессный lock,
  native check и ту же транзакцию. Отсутствие файла/команды больше не считается
  универсальным успешным результатом. Restore не исполняет импортированный hook.
- На `.117` пройдены настоящий отказ nft, ошибка policy routing после успешного
  kernel commit и ENOSPC в отдельной tmpfs 16 КиБ. Старые правила/файлы/DHCP
  восстановлены; исходные hooks и policy routing стенда возвращены.
- Самообновление запускает watchdog из обязательной копии старого бинарника на
  той же FS в отдельной Linux session. Handshake предшествует замене, arm делается
  rename. Независимый процесс перезапускает панель, требует три ответа с SHA
  именно загруженного executable (`/proc/self/exe`), при отказе возвращает копию
  и проверяет API прежней панели. Чужой/manual replacement не перезаписывается.
  Отсутствующий init-скрипт или не запустившийся watchdog отменяют обновление.
- Настоящие отдельные процессы `.117`: успешное обновление — 4,3 с; намеренно
  сломанная новая панель — откат и готовый прежний API за 49,4 с. Watchdog имеет
  отдельный session ID. Unit-сценарии дополнительно проверяют неправильный SHA,
  отказ restart, отказ восстановления и замену бинарника оператором.
- Start/restart ждут стабильный managed PID. Функциональная проверка сравнивает
  baseline и результат: DNS localhost:53, полный HTTPS-ответ через живой HTTP
  inbound и отдельные VPN-транспорты с сохранением цепочек dialerProxy.
  Используются две независимые контрольные цели; отказ одной не отменяет обновление.
  При исходном сбое/WAN outage результат отмечается `inconclusive`, а не успешной
  полной приёмкой. Предел — четыре используемых VPN-выхода, два пробных процесса
  одновременно. LAN/TPROXY этой проверкой не сертифицируется.
- На `.117` настоящий restart подтвердил DNS и оба используемых VPN-транспорта.
  Проверка строгого tunnel probe теперь отвергает усечённый HTTP 200 и ответы
  свыше 64 КиБ; TLS-сертификаты остаются обязательными.
- SDK recipe собирает `cmd/ruopenray-ui`, включает embedded web и версию,
  использует immutable source ref. Свежая установка генерирует пароль в root-only
  `initial-password`; заданные credentials сохраняются. Удаление пакета сначала
  транзакционно отключает свой перехват, upgrade его не отключает. Пакетные
  install/upgrade/remove и продолжительная приёмка ещё выполняются.
- Для OpenWrt 25.12.4 нужен APK, не IPK. SDK x86/64 скачан из официального
  каталога, SHA-256 `28e004c1be4d215d19c1f12a6aa4c8d8f80689549eb707d0ff5a71f16fa8d05f`
  подтверждён. Пакеты старых OpenWrt/opkg отдельно пока не проверены.

`.1` не используется для испытаний второго пакета. По отдельному разрешению
пользователя там добавлен только `full:shopify.privy.com` в существующий GL.iNet
VPN-маршрут; после короткого restart страница GL-BE14000 проверена в браузере.

- SDK install выявил, что поверх ручной установки OpenWrt `start` сохраняет старый
  процесс. Postinst теперь явно перезапускает только UI. Init AdGuard переносится
  в `/usr/share/ruopenray-ui/ruopenray-adguard.init` как шаблон: package manager не
  должен останавливать независимый DNS при upgrade/remove панели. Проверочный
  артефакт r1 был только на `.117`; переход с него требует вернуть прежний init
  AdGuard из lab backup. Выпускавшимся пользователям этот артефакт не раздавался.
- Linux SDK Go 1.26: полный `go test -race ./...` пройден. Первый APK собран
  (4,5 МиБ); UCI, Xray/AdGuard PID, DNS, firewall и сеть при install сохранены.
  Окончательная проверка APK после исправления postinst ещё выполняется.

- Финальный APK r3 с immutable Go source `b08a8b7` прошёл upgrade/remove/reinstall:
  UCI/пароль, профили, активный конфиг и черновик совпали; Xray/AdGuard PID и DNS/
  firewall/network не менялись. Отдельно удаление с реально включённым безопасным
  перехватом для несуществующего `ruopenray-lab0` очистило nft/policy/hooks и
  сохранило процессы VPN/DNS. После теста пакет снова установлен.
- `ifupdate`, настоящий fw4 reload и reboot `.117` восстановили persistent nft и
  policy routing без дублей и сохранили конфиги/credentials. Артефакт для reinstall
  пришлось повторно скопировать после reboot: `/tmp` очищается (ошибка harness).
- DNS без основного Xray: успешны UDP/TCP, положительные ответы и уникальные
  запросы мимо кеша; после start функциональное здоровье восстановлено.
- Перед длительным прогоном обнаружено, что профиль `.117` содержит только
  SOCKS `127.0.0.1:10808`. Первый harness ошибочно проверял стандартный HTTP-порт;
  это отказ проверки, не отказ VPN (оба туннеля/DNS прошли). Рабочая runtime-health
  теперь выбирает фактический HTTP/SOCKS listener, учитывает auth и wildcard bind.
  Новый native restart проверил также действующий SOCKS. Для финальной сборки
  source ref и package release будут обновлены перед чистым 30-минутным прогоном.
