# Пилот B4 — 6 октября 2026

Проверки выполнены на отдельной VM `192.168.50.117`: OpenWrt 25.12.4 x86_64, ядро Linux 6.12.87, Xray 26.3.27, AdGuard Home 0.107.79. Производственный роутер `192.168.50.1` в рамках B4-пилота не изменялся. Прозрачный перехват всего LAN-трафика не включался; существующие неприменённые изменения панели сохранились.

## Установка и изоляция

Использован официальный B4 1.85.0, архив `b4-linux-amd64.tar.gz`. SHA-256 проверен по digest релиза GitHub:

```text
4cf02a7967369c62ec592341a58b66f34b65cb83b352d57aca16b22ae38cc4f3
```

Установлены подписанные пакеты OpenWrt `kmod-nfnetlink-queue` и `kmod-nft-queue` под действующее ядро. B4 работает через procd, бинарник `/usr/bin/b4`, конфигурация `/etc/b4/b4.json`, авторизованный веб-интерфейс на порту 7000. API панели обращается к нему только через loopback. Пароли и конфигурации с секретами в Git не сохранены.

Параметры пилота: внешняя NFQUEUE 537–538, два потока, packet mark B4 `32768`, IPv4/IPv6 включены, `system.tables.skip_setup=true`. TUN, SOCKS/MTProto B4, DNS и маршрутизация сетов выключены. Тестовый сет содержит `example.com` и `example.org`, использует TLS record fragmentation; `faking.sni=false` задан явно. Отключение стратегии fake-пакетов само по себе не отключает SNI faking.

Для проверки в Xray временно добавлялись только два доменных маршрута через выделенный `direct-b4` с socket mark `524288`. Остальные правила, VPN и путь DoH сохранялись. Выделенная таблица `inet ruopenray_b4_direct` ограничивала очередь отмеченными TCP 80/443 и UDP 443 и ответами этих соединений. Основной Xray перезапускался только на тестовой VM.

## Итоговое состояние и возврат

B4 запущен, API подключён. Очередь RuOpenRay выключена, временные доменные маршруты удалены, исходные правила Xray и firewall восстановлены. Выход `direct-b4` оставлен подготовленным в действующей конфигурации и профиле `subscription-test`, но ни одно исходное правило на него не перенаправлено. До ручного выбора маршрутов B4 не обрабатывает пользовательский трафик.

Резервные копии на VM находятся в `/etc/ruopenray-ui/backup-b4-pilot/`: `ruopenray-ui.before`, `xray.before.json`, `xray.traffic-before.json`, `profile.before.json`. Возврат требует сначала выключить выделенную очередь, остановить B4 и его автозапуск, затем восстановить нужные конфигурацию/профиль и бинарник панели. Подготовленный выход можно удалить отдельно, если на него больше нет ссылок. Удалять весь ruleset или чужие таблицы не требуется.

Перед переносом на рабочий роутер нужны его собственные проверки модулей ядра, маркировки, портов, VPN, DNS/DoH и реальных клиентов. Файлы с адресами серверов и секретами нельзя копировать или публиковать из пилота без адаптации. Инструкция интеграции: [b4-integration.md](b4-integration.md).
