# B4 в RuOpenRay

В «Интеграциях» доступны подключение локального API B4, состояние движка, статистика соединений, список сетов, включение/выключение сета, добавление домена и проверка совпадений. Кнопки «Открыть B4» и «Создать или настроить сет» ведут в штатный интерфейс B4 на адресе роутера. Стратегии DPI, IP-цели, geosite, порядок сетов и расширенные параметры редактируются там. Профиль AmneziaWG для B4 не требуется.

Интеграция проверена с [B4 1.85.0](https://github.com/DanielLavrushin/b4/releases/tag/v1.85.0). Панель не устанавливает B4 и не включает общий перехват автоматически. У B4 должен быть свой OpenWrt-сервис `/etc/init.d/b4` и рабочие модули NFQUEUE.

## Подключение API

1. В админке B4 включить авторизацию и задать пользователя.
2. В RuOpenRay → «Интеграции» → «Подключение API B4» указать числовой loopback-адрес, например `http://127.0.0.1:7000`, логин и пароль B4. Нажать «Проверить и сохранить».
3. Проверить состояние движка, версию и доступность сетов. Само подключение API не меняет маршруты Xray или firewall.

Пароль сохраняется на роутере в `DataDir/b4-api.json` с правами `0600`, вне профилей Xray и диагностического пакета. Полная резервная копия данных панели включает этот файл и должна храниться как конфиденциальная. Токен B4 хранится только в памяти; после его истечения или перезапуска B4 панель входит снова. Пустой пароль сохраняет прежний только для того же адреса и пользователя. Повторные ошибки авторизации временно приостанавливают попытки входа.

Клиент не использует системный HTTP-прокси, не следует редиректам и не принимает удалённые адреса API. Кнопка админки заменяет loopback на адрес роутера, сохраняя протокол и порт; доступность этого порта из LAN задаётся в B4 и firewall роутера.

Изменения сетов используют `GET` полного сета и `PUT` с его `revision`: методы и остальные цели сохраняются, устаревшая ревизия отклоняется. Добавление домена не удаляет его из других сетов. Для старых версий API без `revision` доступен просмотр, а редактирование остаётся в админке B4. Проверка домена показывает совпадения с целями B4 и не определяет маршрут Xray.

## Выбранные маршруты через B4

Совместная работа использует отдельный выход `direct-b4`, а не общий перехват интерфейса. Трафик сначала выбирает маршрут в Xray; B4 обрабатывает только явно выбранный прямой выход.

```text
Правило Xray → «Напрямую через B4» (direct-b4)
  → socket mark 0x80000 → ограниченная NFQUEUE → B4 → интернет

Обычный direct / VPN / AmneziaWG → существующий маршрут
AdGuard → DoH → отдельный маршрут DNS в Xray
```

1. В B4 выбрать режим `nfqueue`, установить `system.tables.skip_setup=true`. Отключить маршрутизацию и DNS в активных сетах. Packet mark B4 должен быть отдельным; проверенный вариант — `32768` (`0x8000`).
2. В RuOpenRay нажать «Подготовить выход в черновике». Создаётся отдельный `freedom` с тегом `direct-b4` и `streamSettings.sockopt.mark=524288` (`0x80000`). Обычный `direct`, VPN и правила сохраняются.
3. Выбрать «Напрямую через B4» для нужных правил Xray, проверить черновик и применить конфигурацию. Не направлять DoH через этот выход, если DNS должен идти через VPN.
4. Запустить B4, затем нажать «Включить direct → B4». Панель проверит активную конфигурацию Xray, фактический внешний движок, слушающий диапазон NFQUEUE, конфликты меток и чужие очереди.

Панель владеет только таблицей `inet ruopenray_b4_direct`. В неё попадают TCP 80/443 и UDP 443 выбранного выхода, а также ответы этих соединений через conntrack mark. Обрабатываются первые 20 TCP-пакетов и 9 UDP-пакетов в каждом направлении; поддерживаются семейства IPv4/IPv6, включённые в B4. Пакеты, созданные B4, пропускаются по его собственной метке. Порт обычного DNS 53 исключён. DoH использует 443, поэтому его маршрут определяется правилами Xray и требует отдельного выбора.

Правила проверяются `nft -c` и применяются атомарно. `queue bypass` пропускает трафик при остановленном B4. Если разрешённая очередь удалена при перезагрузке firewall, панель восстановит свою таблицу с повторной проверкой условий. После изменения диапазона очередей в B4 нужно перезапустить движок и нажать «Обновить очередь».

TUN B4, его встроенный общий firewall, конфликтующие метки, другие правила NFQUEUE и активные сеты с собственной маршрутизацией/DNS блокируют совместный запуск или включение перехвата. Пока очередь включена, применение Xray-конфига, который удаляет выход `direct-b4` или отдаёт его метку другому выходу, отклоняется; сначала нужно выключить очередь. Сохранение неактивных профилей остаётся доступным. Настройка DPI зависит от провайдера и сайта: наличие очереди само по себе не подтверждает успешный обход.

## Отключение и API панели

«Отключить direct → B4» удаляет только таблицу RuOpenRay и выключает её восстановление, сохраняя маршруты Xray. «Остановить B4» останавливает движок; очередь остаётся с `bypass`. «Очистить таблицы B4» сначала успешно останавливает сервис, отключает очередь RuOpenRay, затем вызывает штатную очистку B4. Обычный VPN, AdGuard и их процессы эти действия не перезапускают.

Ручки требуют существующей авторизации RuOpenRay:

| Ручка | Назначение |
| --- | --- |
| `GET /api/compat/status` | Свежий статус компонентов; `b4.api` содержит безопасное представление API |
| `POST /api/compat/b4/connect` | `{url, username, password, clearCredentials?}` — проверить и сохранить подключение |
| `POST /api/compat/b4/api` | `check-domain` с `domain`; `set-enabled` с `id/revision/enabled`; `add-domain` с `id/revision/domain` |
| `POST /api/compat/b4/direct` | `{enabled}` — включить/обновить или выключить выделенную очередь |
| `POST /api/compat/b4` | `{action}` — status/start/stop/restart/enable/disable/clear сервиса |

Полная схема доступна в `/api/openapi.json`.
