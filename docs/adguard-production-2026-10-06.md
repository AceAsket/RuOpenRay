# Прямой DoH и AdGuard на рабочем роутере

6 октября 2026 года интеграция перенесена с тестовой VM `192.168.50.117`
на `192.168.50.1`. Рабочий роутер не перезагружался. Xray не
перезапускался, его бинарник, активная конфигурация, PID, firewall и маршруты
остались прежними.

## Установленная схема

```text
Клиент → dnsmasq:53 → AdGuard Home 127.0.0.1:10536
  → HTTPS напрямую → Google 8.8.8.8 / Quad9 9.9.9.9
```

AdGuard Home — `0.107.79`, проверенный ARM64 релиз; панель —
`0.5.0-test.402+92e843b`, код [92e843b](https://github.com/AceAsket/RuOpenRay/commit/92e843b9386481b17387358247b56ccbc3021ada).
[CI 402](https://github.com/AceAsket/RuOpenRay/actions/runs/37477687895)
успешно проверил Go, 100 frontend-тестов, smoke/boot и совместимость
с Xray `26.3.27` и `26.9.9`. На рабочем роутере осталось ядро `26.3.27`.

Upstream — `https://8.8.8.8/dns-query` и `https://9.9.9.9/dns-query`.
Проверка TLS включена; bootstrap, общий fallback и HTTP proxy пустые.
SOCKS и вспомогательный TLS relay не используются. Native HTTPS-сокеты
процесса AdGuard сопоставлены с исходящими пакетами на WAN.
DNS не зависит от основного Xray; интернет и доступный DoH-сервер всё ещё
необходимы. Прямой TCP DoH не требует изменения политики UDP/443/Vision.

API AdGuard подключён к панели через защищённый loopback адрес.
Для четырёх имён VPN-серверов сохранены автоматические разрешающие правила
и domain-specific DoH upstream. Фильтрация включена, загружен AdGuard DNS
filter. Админка доступна по `http://192.168.50.1:3001/` с отдельной
авторизацией; секреты не включены в репозиторий.

Ранее установленный GL.iNet AdGuard был выключен. Его бинарник и конфигурация
сохранены, прежний неиспользуемый автозапуск отключён. Новый
`ruopenray-adguard` включён в автозапуск. На роутере также обнаружены
прежние файлы B4; B4 остался остановленным, с выключенным автозапуском.
Новая установка, запуск или изменение настроек B4 не выполнялись.

## Проверки перед переключением

На VM проверены прямой DoH, все A/AAAA/TXT/MX/HTTPS запросы по UDP/TCP,
реклама и имена VPN-серверов:

- 28 проверок при работающем Xray.
- 28 при остановленном Xray и заново запущенном AdGuard после очистки кэша.
- По 28 после отката к прежнему relay и возврата к прямому DoH.
- 28 после загрузки VM; оба основных сервиса запустились автоматически.
- 28 при недоступности одного upstream; второй продолжил обслуживать DNS.
- При недоступности обоих upstream обычные запросы вернули SERVFAIL;
  перехода на открытый DNS не произошло.
- Новый UI правильно распознаёт прямой DoH; исключения добавляются и
  удаляются, защита выключается и включается, Xray и настройки сети не меняются.

На рабочем роутере до переключения dnsmasq новый AdGuard прошёл 20
запросов по UDP/TCP через отдельный loopback порт, включая все типы записей
и блокировку рекламы. Оба IP DoH прошли проверку AdGuard с TLS.
Состояние исходного DNS и VPN при подготовке сохранялось.

## Проверки после переключения

28 DNS-проверок с Windows и 28 с VM через LAN к `192.168.50.1:53` прошли.
Шесть HTTPS-проверок через работающий SOCKS Xray прошли с проверкой
сертификатов. Для непрерывной проверки использован YouTube `generate_204`;
его маршрут в VPN подтверждён журналом Xray.
Обе серии непрерывных проверок VPN завершились с результатом 40/40,
включая первоначальный откат и окончательное переключение DNS.
Диагностика DNS панели не вернула предупреждений.

Существующая настройка dnsmasq `filter_aaaa=1` сохранена. Поэтому AAAA
на LAN возвращает NODATA, как до переноса; на отдельном порту AdGuard AAAA
успешно разрешается. Первая проверка ожидала AAAA на LAN и запустила
автоматический откат. Исходные DHCP/DNS настройки восстановились, все
защищённые хеши и PID Xray совпали. После сверки существующего фильтра
повторное переключение и проверки прошли. IPv6 на роутере не включался.

Во время переключений действовал одноразовый пятиминутный откат DNS.
После успешной проверки он снят. Автозапуск проверен на VM; перезагрузка
основного роутера для дополнительной проверки не проводилась.

## Возврат прежнего DNS

Резервные копии панели, её данных, Xray, DHCP, сети, firewall и прежнего
AdGuard находятся в защищённом каталоге рабочего роутера:
`/root/ruopenray-backups/adguard-production-20261006`.

Через независимый SSH-доступ на роутере:

```sh
sh /root/ruopenray-backups/adguard-production-20261006/rollback-dns.sh
```

Скрипт возвращает исходный DHCP/DNS, перезагружает настройки dnsmasq,
останавливает новый AdGuard и восстанавливает прежний флаг автозапуска.
Основной Xray не перезапускается. Обновлённая панель остаётся установленной.
