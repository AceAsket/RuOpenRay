# Прогресс применения и выбор выхода

Исправлен индикатор применения: проверка, перезапуск с проверкой готовности
и обновление состояния отражают фактическую работу. Один POST выполняет
прежнюю транзакцию; отдельный GET наблюдает стадии, включая откат. Ответ
наблюдения не считается разрешением продолжать операции с firewall.

Выбор сервера теперь распознаёт нормализованное правило по умолчанию
`network: "tcp,udp"` и меняет его на прежнем месте. Раньше после такого
правила мог добавляться ещё один выход, до которого трафик не доходил.
Сохраняются метки правил, отдельные направления, условия и прямые правила
устройств, в том числе при выборе балансировщика. Сообщение сообщает фактическое число изменённых правил и отдельно
показывает добавление правила по умолчанию.

Проверки: полный Go suite и vet; 429 frontend-тестов; smoke и загрузка
приложения. Регрессионные тесты проверяют наблюдение во время блокирующего
POST, ошибки и откат, отсутствие повторного применения, настоящий refresh,
замену нормализованного catch-all и сохранение условных маршрутов.
В браузере на синтетическом API с настоящим интерфейсом проверены переходы
трёх этапов, отказ проверки и откат. Зависший GET наблюдения прерывается через
четыре секунды; это не повторяет и не отменяет POST применения.

Проверка провайдерских выходов на основном роутере показала успешный HTTPS
через четыре уже добавленных TLS-выхода. Изменять их протоколы или ключи для
этого исправления не требуется. Автоматическое перенаправление отдельных
групп правил на выбранный сервер не выполняется.
