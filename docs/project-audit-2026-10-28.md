# Аудит проекта и очередь после 0.5.1-rc3

Расширенный аудит текущего `dev`, локальные воспроизведения дефектов и полная
очередь приёмки: [полный инженерный аудит](full-project-audit-2026-10-28.md).

Ход исправлений: [план реализации и результаты испытаний](reliability-implementation-plan.md).

Область: исходники, история `dev`/`5.0-test`, выпуск, результаты CI и ранее
выполненные сетевые проверки `.117`/`.1`. Это не повторная установка панели
или ядра на роутеры и не полная проверка всех сторонних VPN/версий B4.
Стабильная 0.5.1 пока не объявляется готовой.

## Что закрывает RC3

- В `dev` объединяются 52 новых коммита тестовой ветки и три его собственных
  коммита. Актуальный мастер `connection/scenarios/launch`, интеграции AdGuard/B4,
  анализ правил и резервирование сохраняются из проверенной тестовой версии.
  Старый вариант мастера `connection/traffic/verify` не смешивается с ним.
  Из `dev` сохраняются тестовые фикстуры, проверка секретов, читаемые подписи
  и обнаружение старого AWG-профиля; два теста проверяют результат слияния.
- Пустые исключения сниффера очищаются, а native config validation дополнена
  защитой от семантически опасного обновления ядра.
- Проверки настоящих TLS-туннелей, failover и всех стратегий балансировки,
  HTTP/TLS-сниффинга входят и в CI, и в обязательный этап публикации релиза.
- Сканер больше не принимает безопасные `example.test`, TEST-NET и `2001:db8`
  за личные VPN-ссылки. Он включён в CI; отрицательная проверка должна всё ещё
  обнаруживать ссылку на посторонний хост.
- Исправлены относительные имена бинарников в публикуемых SHA-256: файлы
  проверки работают из каталога загрузки без создания служебного `dist/`.
- Сборочный SDK обновлён с Go 1.22 до закреплённого Go 1.27.3, который
  [официальный каталог Go](https://go.dev/dl/?mode=json) помечает стабильным.
  Локальные тесты и `go vet` выполнялись этой же версией; `go.mod` сохраняет
  минимальную версию языка. Проверка скрытых файлов сканером исправлена для Linux.
- Внешний каталог содержит исправление скрипта локализации Discord. Его
  применение на `.1` после отдельного разрешения проверено: восемь полных
  загрузок скрипта, видимая главная страница и API Discord. DNS и остальные
  изменения черновика сохранены.

## Следующий этап после базовой стабильности

| Приоритет | Задача | Проверка результата |
| --- | --- | --- |
| P2 | Безопасное обновление группы из внешней подборки | Предпросмотр добавленных/удалённых условий с сохранением group ID, назначения, пользовательских исключений и порядка; без автоматического применения. Сейчас обновление источника обновляет только шаблоны. |
| P2 | Улучшить объяснение фактического маршрута | Показывать отличие исходного IP, sniffed-домена и DNS Xray; отделять расчёт по черновику от подтверждения журналом рабочего ядра. Не объявлять доступность сайта по одному HTTP 200 без чтения тела. |
| P2 | B4: исправить политику UDP reject и проверить реальный DPI | Контроль повторных QUIC Initial, возврат браузера к TCP, drop/reject, перезапуск firewall и независимость DNS/VPN. Текущий лимит очереди девятью пакетами не обеспечивает постоянный reject. Включение B4 на `.1` в этот выпуск не входит. |
| P2 | Native IPv6 TPROXY | Отдельные IPv6 inbound, nft/policy routing, исключения и проверки LAN→WAN. Успешный IPv6 outbound или временные тестовые правила не подтверждают штатный LAN-перехват. |
| P2 | Повторяемая UI-приёмка и восстановление на другой системе | Сохранение форм при фоновом обновлении, мобильные ширины, подборки/балансировщики и ошибки API; полное восстановление на чистой VM с установленными службами. Архив не содержит бинарники, geo-базы и native B4. |
| P2 | Уточнить каналы сборок и способ установки RC | Контролируемый переход с `0.5.1-test.*` на RC, скрипты конкретного тега и стабильный Latest; не смешивать `main` со свежим `dev` и не предлагать автоматическое понижение. |
| P2 | Синхронизировать Node dev-server с Go backend | Локальный Node-макет предлагал RC2 поверх RC3, а настоящий Go-бинарник корректно отклонил понижение. Перенести ту же модель версий в макет и проверять обновления контрактными тестами; релизную приёмку выполнять настоящим бинарником. |
| P2 | Обслуживание runtime CI | Обновить Node/frontend и версии Actions после отдельной проверки; GitHub уже сообщает предупреждение о старом Node 20 runtime Actions. Закреплять совместимые версии и проверять поведение на целевых платформах. |

Источник клиента DNS в AdGuard за dnsmasq остаётся localhost. Перенос AdGuard
на порт 53 не планируется автоматически: пользователь сохранил существующую
схему. DNS parser в мониторе RuOpenRay — отдельная возможность и не меняет
источник в журнале AdGuard.

## Порядок работ

1. Выпустить RC3 из `dev` после CI; `main` и роутеры не обновлять этим действием.
2. Выполнить P1-координатор операций и тесты конкурирующих запросов на `.117`.
3. Проверить опубликованный RC3, DNS/VPN, восстановление и перезагрузку на `.117`.
4. Отдельно довести SDK-пакет и функциональную проверку обновления ядра.
5. После критериев P1 подготовить стабильную 0.5.1; B4/IPv6 вести отдельно.

Проверенные механизмы уже описаны в [совместимости Xray](xray-compatibility.md),
[резервировании](vpn-failover.md), [восстановлении](backup-restore.md) и
[сетевом аудите](xray-audit-2026-10-28.md). Проверка пакетов SDK и окна
конкурентной записи остаются задачами, а не заявленными успешными тестами.
